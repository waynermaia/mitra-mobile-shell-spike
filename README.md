# mitra-mobile-shell-spike

Spike (2026-11-05): wrap an app published by Infusion in a Capacitor shell and take it to
internal testing (Google Play) and TestFlight (Apple). Companion note:
`vault/20-projects/superficie-apps-stores/spike-apps-nas-stores-2026-11-05.md`.

Target app: **Bolo Mobile Spike**, created in Infusion for this test. Published URL (https://a1-a17htrxztqy0pw4apmihj62ou.infusion-ai.cloud) lives in
`capacitor.config.json` (`server.url`).

## What is here

- `capacitor.config.json`: app id `cloud.infusion.bolomobilespike`, WebView loading the
  published app. Spike only: production must bundle the web assets into `www/`.
- `www/index.html`: offline fallback page (bundled assets, not used while `server.url` is set).
- `assets/`: logo as SVG; `npm run assets` regenerates every icon and splash for both platforms.
- `android/`, `ios/`: native projects generated by `cap add`. iOS uses Swift Package Manager,
  so no CocoaPods on the build machine.
- `.github/workflows/mobile.yml`: three jobs.
  - `android`: signed release AAB and APK as artifact (unsigned when secrets are missing).
  - `ios-simulator`: compile check, no signing.
  - `ios-testflight`: manual run with `upload_testflight=true`; archives with cloud signing
    through an App Store Connect API key and uploads to TestFlight.

Plugins installed: app, splash-screen, status-bar, share, haptics, network, browser,
push-notifications (push needs Firebase on Android and the aps entitlement on iOS; not wired).

## Local commands

```bash
npm ci
npx cap sync            # copies www/ and config into both platforms
npm run assets          # regenerates icons and splash from assets/*.svg
npx cap open ios        # needs Xcode (not installed on this Mac)
npx cap open android    # needs Android Studio (not installed on this Mac)
```

Android release build locally (needs Android SDK): source `.secrets/android-signing.env`,
export `ANDROID_KEYSTORE_PATH=.secrets/upload-spike.jks`, then `cd android && ./gradlew bundleRelease`.

## Morning checklist: what only the account owner can do

### Google Play (internal testing)

1. Have a Play Console developer account (USD 25 once). Organization accounts need a D-U-N-S
   number; personal accounts created after 2023-11-13 must run a closed test with 12 testers
   for 14 days before production (internal testing is not blocked by that).
2. Play Console: Create app -> name "Bolo Mobile Spike", app, free. Fill the mandatory
   declarations (privacy policy URL, data safety, content rating, target audience).
3. Download the `android-release` artifact of the last green run and upload the `.aab` to
   **Testing -> Internal testing** by hand. The first upload of every app must be manual; the
   Play Developer API only works after that.
4. Add testers (e-mail list) and share the opt-in link.
5. Later, for automation: Play Console -> Setup -> API access -> service account; store the
   JSON as a secret and add an `upload-play` job (Gradle Play Publisher or `r0adkll/upload-google-play`).

The upload keystore for this spike is in `.secrets/upload-spike.jks` (git-ignored) and in the
repo secrets `ANDROID_KEYSTORE_B64`, `KEYSTORE_PASSWORD`, `KEY_ALIAS`, `KEY_PASSWORD`. Play App
Signing lets Google hold the final key, so this upload key can be reset later.

### Apple (TestFlight)

1. Apple Developer Program membership (USD 99/year) on the account that owns the app. For a
   company, enrollment needs a D-U-N-S number and can take days.
2. App Store Connect -> Users and Access -> Integrations -> App Store Connect API -> generate a
   **Team** key with role **App Manager**. Note the Key ID and the Issuer ID and download the
   `.p8` once (it cannot be downloaded again).
3. App Store Connect -> Apps -> `+` -> New App: platform iOS, name "Bolo Mobile Spike", bundle
   ID `cloud.infusion.bolomobilespike` (register it under Certificates, Identifiers and
   Profiles if it is not listed), SKU `bolo-mobile-spike`. Creating the app record is not
   covered by the API as far as this spike could confirm.
4. Repo secrets: `ASC_KEY_ID`, `ASC_ISSUER_ID`, `ASC_KEY_P8_B64` (`base64 -i AuthKey_XXXX.p8`)
   and `APPLE_TEAM_ID` (Membership details).
5. Actions -> Mobile shell -> Run workflow with `upload_testflight` checked. The job archives
   with `-allowProvisioningUpdates` (creates certificate and profile on the account) and
   uploads. The build appears in TestFlight after Apple's processing (minutes); add internal
   testers there.
6. Before a real App Store submission: Sign in with Apple if the app offers Google login,
   privacy policy URL, and native features beyond the WebView (guideline 4.2).

## Social sign-in inside the shell (proved on the emulator, 2026-11-05)

A plain WebView cannot finish Google sign-in: Capacitor sends any host outside `server.url`
to the system browser, and in popup mode the web app waits for a popup answer that never
arrives. What works, end to end on a Pixel 7 emulator (API 35):

1. The web app calls `signInWithGoogle({ mode: 'redirect' })` when `window.Capacitor` exists
   (the Bolo app does this since its second publish). The SDK stores the CSRF context in the
   WebView's `sessionStorage` and navigates to the auth page; Capacitor opens that in Chrome.
2. Chrome runs the auth page and Google, then the auth page redirects to the app origin with
   `#codeMitra=...&stateMitra=...`.
3. The manifest declares an App Link (`autoVerify`) for the app host, so Android hands that
   URL to the shell instead of Chrome. `MainActivity.onNewIntent` loads it in the WebView
   with a fresh `shellLink` query value, which forces a full document load.
4. The app boots, `completeGoogleSignInRedirect()` finds the fragment and the context,
   exchanges the code at IAM, and the user is signed in.

On the emulator the domain was approved by hand:

```bash
adb shell pm set-app-links --package cloud.infusion.bolomobilespike 2 <app host>
adb shell pm set-app-links-user-selection --user 0 --package cloud.infusion.bolomobilespike true <app host>
```

Production needs the platform to serve `https://<app host>/.well-known/assetlinks.json`
(package name + upload certificate SHA-256) and, for iOS, `apple-app-site-association`.

WebView inspection: `webContentsDebuggingEnabled` is on in `capacitor.config.json`;
`adb forward tcp:9333 localabstract:webview_devtools_remote_<pid>` exposes the DevTools
protocol on `http://localhost:9333/json`.

Emulator setup used here (no Android Studio): `sdkmanager emulator
"system-images;android-35;google_apis;arm64-v8a"`, `avdmanager create avd -n spike35 -k ... -d pixel_7`,
then `hw.keyboard=yes` in `~/.android/avd/spike35.avd/config.ini` so the Mac keyboard works.

## Findings to carry into the Proposal

- Both stores require the content owner's own account; the platform can automate everything
  after an API key (Apple) and a service account (Google) are handed over.
- The two manual steps that remain are "create the app record" (Apple) and "first upload"
  (Google).
- iOS builds need macOS; GitHub Actions `macos-15` worked for this spike without any local
  Xcode.
